# bytode v0.1 — Design Spec

## Overview

**bytode** is a terminal coding agent. It follows a ReAct loop pattern with a
long-context DeepSeek model (`deepseek-v4-pro`), structured tool calling, LSP
integration, and project-aware tool registration. Written in Rust, focused on
Rust projects for v0.1.

Key design principles:

- **Structured data only** — build output is JSON, diagnostics come from LSP,
  never parse text.
- **Deterministic where possible** — project detection, tool registration,
  memory compression all happen in Rust code, not LLM reasoning.
- **Token-conscious** — cut noise aggressively. SOP injected only on failure.
  Tool list cropped to project. Prefix-cache everything static.
- **No shell** — Agent has zero access to a generic shell. Every operation
  goes through a typed tool trait.

```
├── lsp/

    └── approve.rs   # write_file approval dialog
```

### Data flow

```
User input
  → ReAct loop
    → ContextBuilder.build()
      → Core (always) + Memory (summary + recent) + SOP (on failure)
    → DeepSeek API (streaming)
    → Parse response: Text (print) | ToolCall (dispatch)
    → Tool.execute()
      → ToolResult (structured, JSON-prioritised)
    → Render result
    → SOP check
    → Loop (next inference)
```

## 2. Three-Layer Prompt System

### Layer 1: Core (always present, prefix-cache anchor)

- Role definition ("Rust coding agent in terminal")
- Behaviour rules (read-before-write, cite file:line, diagnose-first)
- Tool descriptions (cropped to project)
- Project snapshot (~100 tokens, from ProjectProfile::snapshot())

### Layer 2: SOP (conditionally injected)

Triggered when the previous tool result is a build/test failure.
Contains mandatory diagnose-first workflow, prohibits grep/raw-text parsing,
demands adversarial verification before claiming done.

### Layer 3: Memory (rolling window + compression)

- Last N turns kept in full (N=10 default)
- Older turns compressed to structured summary:
  - Task description
  - Files modified
  - Errors resolved
- Compression threshold: 80% of context window used
- Compression is deterministic (Rust code), not LLM-summarised

### Partition management

```rust
pub fn build(&self, turn: &Turn) -> Vec<Message> {
    let mut messages = Vec::new();
    messages.push(self.core.build_system());          // 1. core (cache anchor)
    if let Some(s) = self.memory.summary() {
        messages.push(Message::system(s));            // 2. compressed summary
    }
    messages.extend(self.memory.recent_turns());      // 3. recent turns
    if self.sop.should_activate(turn) {
        messages.push(Message::system(self.sop.build())); // 4. SOP (conditional)
    }
    messages.push(turn.current_message.clone());      // 5. current user/tool msg
    messages
}
```

### Tool result formatting

- Structured data (Diagnostics, JSON) → full JSON, never truncated
- Text output → head (150 lines) + tail (30 lines) + skip count
- File content → with line numbers, by-range pagination

## 3. Tool Trait & Primitives

### Core trait

```rust
#[async_trait]
pub trait Tool: Send + Sync {
    fn name(&self) -> &'static str;
    fn description(&self) -> &'static str;  // must state WHEN-NOT-TO-USE
    fn parameters_schema(&self) -> Value;   // derived from struct via #[derive(ToolArgs)]
    async fn execute(&self, args: Value) -> Result<ToolResult, ToolError>;

    fn requires_approval(&self) -> bool { false }
    fn timeout_ms(&self) -> u64 { 30_000 }
    fn cooldown_ms(&self) -> u64 { 0 }
    fn max_consecutive_calls(&self) -> Option<u32> { None }
}
```

### ToolArgs derive macro

Generates JSON Schema from Rust struct fields, preserving doc comments as
`description`, and `#[arg(minimum, maximum)]` attributes as schema constraints.

### ToolResult — structured by default

```rust
#[derive(Serialize)]
#[serde(tag = "type")]
pub enum ToolResult {
    FileContent { path, content (with line numbers), line_count, total_bytes },
    Diagnostics { tool, total, errors, warnings, list: Vec<Diagnostic> },
    Json { tool, filter: Option<String>, count, data: Vec<Value> },
    Matches { pattern, count, items: Vec<Match>, truncated: bool },
    WriteConfirmation { path, bytes_written, lines, diff: String },
    Text { source, content, truncated: bool },  // fallback only
}
```

### v0.1 tools

| Tool | Category | Availability | Safety |
|------|----------|--------------|--------|
| read_file | ReadOnly | Always | — |
| write_file | Modification | Always | Requires approval, returns diff, writes to tmp first |
| search_code | ReadOnly | Always | ripgrep --json, max results, dir filtering |
| run_check | Build | PrimaryLanguage(Rust) | Hardcoded `cargo check --message-format json`, accepts jq filter |
| get_diagnostics | ReadOnly | DetectedLanguage | Reads LSP publishDiagnostics cache, jq filter support |

### Tool filtering (user-controlled)

`.bytode.toml` `[tools]` section: `enabled = [...]` (exact list), `enable = [...]` (append),
`disable = [...]` (remove from defaults). Empty = project-detected defaults.

```toml
[tools]
enabled = ["read_file", "write_file", "search_code", "run_check", "get_diagnostics:rust"]
# or: disable = ["run_test"]
# or: enable = ["get_diagnostics:python"]
```

## 4. LSP Client — rust-analyzer

### Architecture

```
tools/lsp_diag.rs    → Tool trait impl, reads cache
lsp/client.rs        → LspClient: process mgmt + JSON-RPC
rust-analyzer        → subprocess, stdin/stdout
```

### Lifecycle

- **Lazy start** — first `get_diagnostics` or first file opened triggers init
- **Init handshake** — `initialize` (with capabilities + initializationOptions) → `initialized`
- **Background** — daemon, heartbeat health check, auto-restart on crash
- **Graceful shutdown** — `shutdown` → `exit` → wait 5s → kill

### initializationOptions

Sourced from `.rust-analyzer.toml`, parsed as `toml::Value → serde_json::Value`,
passed through to LSP init untouched. No bytode-owned LSP schema.

```toml
# .rust-analyzer.toml (user's existing config)
rustc = { source = "discover" }
checkOnSave = { command = "check" }
diagnostics = { enable = true }
```

### Diagnostics cache

- `textDocument/publishDiagnostics` notifications → push to in-memory `HashMap<path, Vec<Diagnostic>>`
- `get_diagnostics` tool → reads cache, zero latency (except cold start)
- `Diagnostic` type maps LSP 0-based positions to 1-based for display

### Read loop

Single tokio task reads stdout line-by-line:
- `"id"` present → response, match to pending request
- `"method"` present → notification, dispatch by method name
- Diagnostics notifications → update cache

## 5. Configuration System

### Three-tier cascade

```
1. Code defaults (safety-first)
2. ~/.config/bytode.toml (user preferences)
3. <project>/.bytode.toml (project-specific, highest priority)
```

### .bytode.toml structure

```toml
[project]
lang = "rust"               # manual override (optional)

[build]
extra_check_flags = ["--all-targets"]

[tools]
# enabled = [...]           # exact tool list
# enable = [...]            # append to defaults
# disable = [...]           # remove from defaults

[tools.search]
ignore_dirs = ["target", ".git", "node_modules"]
max_results = 200

[agent]
confirm_before_write = true
max_consecutive_calls = 20
auto_check_after_write = true

[security]
max_file_size = 1_048_576
forbidden_write_patterns = ["/etc/*"]
```

### Hard constraints (user cannot override)

- `cargo check` always includes `--message-format json`
- Security `forbidden_write_patterns` always includes system paths
- LSP command is `rust-analyzer` for v0.1

### LSP options

Not duplicated. `.rust-analyzer.toml` is the single source; bytode reads it and
passes through. No `[lsp.options]` in `.bytode.toml`.

## 6. Project Detection

### Strategy: marker-file scan (deterministic, zero LLM tokens)

```rust
const MARKERS: &[Marker] = &[
    // Rust
    Marker { file: "Cargo.toml", language: Rust, build: Cargo,
             content_check: Some(|c| c.contains("[package]") || c.contains("[workspace]")),
             priority: 100 },
    // Node
    Marker { file: "package.json", language: JavaScript, build: Npm,
             content_check: Some(|c| c.contains("\"name\"")), priority: 80 },
    // Go
    Marker { file: "go.mod", language: Go, build: GoMod,
             content_check: Some(|c| c.starts_with("module ")), priority: 90 },
    // Python
    Marker { file: "pyproject.toml", language: Python, build: Pip,
             content_check: Some(|c| c.contains("[project]") || c.contains("[tool.poetry]")),
             priority: 70 },
    // ... extend as needed
];
```

### Two-phase detection

1. **Scan** — match root directory filenames against MARKERS. Content-check each
   match. Sort by priority.
2. **Deepen** — workspace detection (`[workspace]` members), source dirs
   discovery, test framework identification.

### Output: ProjectProfile

```rust
pub struct ProjectProfile {
    pub primary: Language,               // highest priority match
    pub all_languages: Vec<Language>,     // all detected (incl. glue langs)
    pub build_system: BuildSystem,
    pub test_framework: Option<TestFramework>,
    pub root: PathBuf,
    pub source_dirs: Vec<PathBuf>,
    pub is_workspace: bool,
    pub workspace_members: Vec<PathBuf>,
}
```

### Snapshot injection (~100 tokens)

```
Project: Rust (build: cargo)
Root: /home/user/project
Source: src, tests
```

## 7. UI Design

### Layout

```
┌──────────────────────────────────┬──────────┐
│                                  │  Tools   │
│  Content area (scrollable)       │  ─────   │
│                                  │  📖 read  │
│  LLM output / tool results       │  ✏️ write │
│  user input                      │  🔍 search│
│                                  │  🔧 check │
│                                  │  💉 diag  │
│                                  │          │
│                                  │  L: Rust │
│                                  │  D: auto │
├──────────────────────────────────┴──────────┤
│ bytode │ ~/D/proj │ master ✓ │ 🔍 diag │ ctx ██░ 214K/1M │
└──────────────────────────────────────────────┘
```

- **Content area (left)** — main interaction surface
- **Tools sidebar (right, 24 cols)** — active tool list, grouped by layer.
  Toggle: `Ctrl+T`. Default collapsed.
- **Status bar (bottom, 1 row)** — `name │ path │ branch │ task │ model │ ctx bar`

### Status bar fields

```
bytode │ ~/D/bytode │ master ✓ │ 🔍 diagnosing │ deepseek-v4-pro │ ctx ██░ 214K/1M
──────   ──────────   ────────   ──────────────   ────────────────   ────────────────
name     cwd (short)  branch     current task     model              context usage
                       + dirty
```

Context bar: `█████░░░░░ 847K/1M` with `⚠` suffix when >90%.

### Modes

- **REPL** — `bytode` (no args). Interactive loop with `/` commands.
- **One-shot** — `bytode "fix all compile errors"`. Runs task, prints result, exits.

### Slash commands

| Command | Action |
|---------|--------|
| `/help` | Show all commands |
| `/expand` | Expand last collapsed result |
| `/diff` | Replay last edit diff |
| `/undo` | Revert last write (`git checkout --`) |
| `/history` | Show tool call history |
| `/context` | Print context stats |
| `/config` | Show loaded config |
| `/mode <name>` | Switch agent mode |
| `/clear` | Clear conversation, keep file changes |
| `/exit` | Quit |

### Approval dialog

On `write_file` (if `confirm_before_write = true`):
- Show truncated diff (max 30 lines)
- Prompt: `[Y]es / [N]o / [V]iew full diff?`
- `V` opens full diff in pager

### Output style

- `rich` (default) — ANSI colours, spinner, boxed summaries
- `plain` — no ANSI, machine-friendly
- `json` — all output as JSON lines (for scripting)

## 8. Safe Editing & Search & Memory

### write_file safety

1. **Path check** — must resolve within project root
2. **Forbidden check** — must not match `forbidden_write_patterns`
3. **Size check** — must not exceed `max_file_size`
4. **Atomic write** — write to `*.bytode_tmp`, `rename` on success
5. **Diff** — compute unified diff against prior content
6. **Approval** — user confirms before write proceeds

### search_code

- Backend: `rg --json --line-number --no-heading`
- Fixed args — user cannot inject flags
- `ignore_dirs` from config
- `max_results` cap with `truncated: true` flag

### Memory compression

- Deterministic, no LLM call
- Extracts: task description, files modified, errors resolved
- Merges new summary into existing summary
- Triggers at 80% context usage

## 10. What's NOT in v0.1

- Multi-language LSP (Go, Python, etc.) — detection framework exists, code deferred
- `find_definition` / `find_references` LSP tools — `get_diagnostics` only
- `run_test` — deferred to v0.2
- `edit_block` (safe search/replace) — `write_file` is full-file for now
- MCP protocol — not in scope
- Model routing / multi-model — `deepseek-v4-pro` only
- Memory: true token counting via tokenizer (currently 1 tok ≈ 4 chars estimate)

## 11. Startup Sequence

```
1. Parse CLI args (clap)
2. Load config (.bytode.toml → ~/.config/bytode.toml → defaults)
3. Detect project (ProjectProfile::detect)
4. Initialise LspClient (does not start rust-analyzer yet)
5. Register tools → activate_for(profile, config)
6. Build Core prompt layer (cached for session)
7. Init terminal (ratatui + crossterm raw mode)
8. Enter REPL or One-shot mode
9. On exit: shutdown LSP, restore terminal
```
